# Mains question quality benchmark

ScoreFree uses these public practice pages as **difficulty and format benchmarks**, not as permission to copy their question text. Providers can change access and terms at any time; link out for their questions unless explicit reuse permission or an open licence is confirmed.

## Acceptance checklist for ScoreFree Mains questions

A question must be checked before it is added to the internal question bank:

- **Quantitative Aptitude:** prefer multi-step arithmetic, caselets and data interpretation sets; include realistic calculations and plausible distractors. Avoid elementary one-step templates as the main bank.
- **Reasoning:** use multi-condition seating/floor/box/month scheduling puzzles, data sufficiency, coded relations and other multi-step Mains formats. A puzzle set must preserve shared directions and data for all linked questions.
- **English:** include reading comprehension, cloze tests, sentence/paragraph rearrangement, contextual vocabulary and grammar-in-context, rather than relying mostly on isolated basic fill-in-the-blanks.
- **General/Financial Awareness:** date current-affairs questions; verify factual answers against primary sources (RBI, NPCI, SEBI, government releases and other relevant official bodies). Do not present stale facts as current affairs.
- **Answer validation:** independently solve every question; check all options, calculations, ambiguity and explanation. For linked DI/puzzle sets, validate every sub-question together.
- **Provenance:** record source, source URL, licence/permission, verification date and answer-review status for every imported question. Keep memory-based papers labelled as reconstructed/reported, not official papers.

## Safe sourcing workflow

1. Discover public pages and identify question formats and difficulty.
2. Check the provider's terms and the specific material's licence before copying anything.
3. If republication is not clearly permitted, link directly to the provider rather than scraping, copying or republishing its questions.
4. Import only clearly reusable content; independently verify its answer key and explanations.
5. Run the question-bank tests and inspect a sample of each subject before deploying.
6. Do not mark the bank as a full-length mock until the actual required number of reviewed questions is present.

The existing question-bank generator is not proof of Mains-level quality by itself. A successful build validates code and answer-key structure, not exam difficulty or factual correctness.
